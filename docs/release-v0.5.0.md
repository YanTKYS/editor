# v0.5.0 公開手順

v0.5.0 はリリース準備中です。最新の公開済み Release は v0.4.0 です。この文書の作成・検証ではタグ作成、Release 公開、Pages 配備を実行しません。

## 収録内容

| 対象 | 内容 |
| --- | --- |
| UX-07・UX-15 | 全タブ置換のプレビューと対象タブ選択。確定前の変更検知と、選択外の本文の保持 |
| UX-13 | 未書き出しタブの ZIP 書き出し。同名ファイル・UTF-8・改行・BOM と保存確認 |
| UX-14 | 最新の差分を比較方向・対象名・日時付きのテキストへ書き出し |
| PR #29 | 全削除時の終了確認、読み込み中の入力保持、書き出し失敗時の案内。「書き出してから閉じる」は保存確認後に終了し、中止時は未書き出し状態を保持 |
| CI・Release | アーティファクト転送と Pages のアクションを Node.js 24 対応版へ更新。アプリのビルドは Node.js 22 |

詳細なリリースノートは [CHANGELOG.md](../CHANGELOG.md) の v0.5.0 節を使用します。保存データのスキーマ変更はありません。

## 公開前の条件

| 確認事項 | 条件 |
| --- | --- |
| 公開対象 | この PR を main にマージしたコミット。package.json と、package-lock.json のトップレベル・packages[""].version の3箇所がすべて `0.5.0` |
| 変更履歴 | `changelog-section.sh v0.5.0 CHANGELOG.md` が同版の節だけを取得できること |
| CI | 公開対象コミットの型チェック・単体・全 E2E・本番ビルド・リリース用スクリプト・配布 ZIP の静的配信確認が成功していること。Release ワークフロー自身には E2E 実行がないため、CI の成功も確認する |
| GitHub Actions | Actions が使用可能で、実行者が Release ワークフローを手動実行できること。build は contents: read、publish は contents: write を使い、標準の GITHUB_TOKEN でタグと Release を操作する。追加の個人トークンは不要 |
| タグ・Release | 初回公開前に v0.5.0 のタグ・Release がないことを確認する。既存タグがある場合はそのコミットがビルド対象になり、移動されないため、意図する対象か確認する |
| Pages | 現在の Deploy ワークフローは main への push（PR マージ）で自動配備する。Release の手動実行とは独立している。マージ時点で Pages も更新されることを確認してからマージする |

準備時点では既存 Release ワークフローの成功実績と Pages の `workflow` 設定を確認しています。管理者向け Actions 許可設定 API は参照権限がなく（403）、設定値は未確認です。公開時は実行者が手動実行できることを確認してください。

## 手順と成果物

1. 公開前の条件を確認し、PR を main にマージする。PR の CI と main の配備結果、対象コミットを確認する。
2. **Actions → Release → Run workflow** でブランチ `main`、入力 `version` を `v0.5.0` にして実行する。
3. build ジョブが選んだ SHA、バージョン照合、変更履歴取得、テスト・ビルドと静的配信確認の成功を確認する。
4. publish ジョブの成功後、次の成果物を確認する。

| 成果物 | 内容 |
| --- | --- |
| Git タグ `v0.5.0` | 初回は実行時点の main のコミットに作成 |
| Release `Web Text Editor v0.5.0` | 下書き作成後に公開。本文は変更履歴の v0.5.0 節 |
| `editor-v0.5.0.zip` | 展開直下に index.html、assets/、favicon.svg、fflate-LICENSE.txt。ソース・node_modules は含めない |
| Actions artifact `release-files` | ZIP と release-notes.md。保持期間7日 |
| build のジョブサマリー | ビルド対象 SHA、ZIP 名・サイズ・SHA-256 |

同じバージョンを再実行すると既存タグのコミットからビルドし、Release 本文と ZIP を更新します。通常の新規公開では再実行は不要です。差し替え時の復旧方法は [README](../README.md#リリースビルド配布用-zip) を参照してください。

## 公開後の確認

- Release が公開済みで、ZIP 名・対象タグ・リリースノートが v0.5.0 で揃っていることを確認する。
- ZIP を展開し、[静的 HTTP サーバー](../README.md#ローカルで配布版を確認する) で配信して起動する。`file://` で直接開く方式は使用しない。
- 「ヘルプ」のバージョン表示が 0.5.0 であること、置換プレビュー・対象選択、ZIP 書き出しと保存確認、差分テキスト、終了時の保存確認を確認する。
- 公開を確認してから、README と変更履歴の「公開準備中／未公開」を更新し、提案一覧の UX-07・13・14・15 を「実装・リリース済」へ移す。公開日を記録する場合も、この時点で実際の日付を使う。
